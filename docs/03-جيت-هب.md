## 🔴 قرار أول: ريبو واحد، مش ثلاثة

الخطة الأصلية كانت ٣ ريبوهات منفصلة. **بعد ما اتبنى الأساس فعليا، هذا طلع غلط.** الصح: **monorepo** — ريبو واحد فيه كل شي.

**السبب:**

الـSRS §1.8.1 بتقول الفرونت اند بيستورد الأنواع من الباك اند. بـ٣ ريبوهات، "يستورد" بتتطلب واحد من:
- تنشر حزمة npm خاصة (حساب + إعداد + نشر مع كل تعديل)، أو
- git submodules (بتكسر عند نص الفريق أول أسبوع)

بريبو واحد + pnpm workspaces، بتصير:
```ts
import { canAcceptOrder } from '@wafa/shared';
```
وخلص. تعدّل النوع بالباك اند → الفرونت اند **ما بيبني** لحد ما ينعدّل.

**وأهم من هيك:** الـPR اللي بيغيّر عمود بقاعدة البيانات + الـAPI + الواجهة بيصير **PR واحد يُراجع مرة وحدة**. بـ٣ ريبوهات بيصير ٣ PRs لازم تُدمج بترتيب معيّن، وأول ما حدا يدمج بالترتيب الغلط بتنكسر البيئة عند الكل.

**"بس ما بنقدر ندير deploy لكل خدمة لحالها؟"** بلى. Railway/Render/Koyeb كلهم بيدعموا "deploy من مجلد فرعي". NFR-07 محفوظة: الخدمتين **مستقلتين بالنشر**، بس **مشتركتين بالمستودع**.

## 1️⃣ إنشاء المنظمة (Organization) — ٥ دقايق

1. [github.com/organizations/plan](https://github.com/organizations/plan) → **Free** → Create
2. الاسم: 🔴 **لا تستخدم اسم البراند** — الاسم لسا غير مقفول. استخدم اسم **محايد ودائم** ما بيتعلّق بأي قرار براند: اسم الفريق، أو الحاضنة، أو أي شي بتقدر تعيش معه سنة.
3. اختر "My personal account" كمالك
4. ادعُ الفريق بإيميلاتهم

> **📌 تصحيح (١٦ أغسطس · متحقَّق من توثيق GitHub):** النسخة القديمة كانت بتقول إن تغيير اسم المنظمة "بيكسر كل روابط الـclone عند الفريق". **هذا غلط.** روابط الويب للريبوهات الموجودة **بتضل تشتغل** بعد إعادة التسمية، والـremotes المحلية عند الفريق بتضل شغالة (مع إن GitHub بينصح تحدّثوها بـ`git remote set-url`).
>
> **اللي بينكسر فعليا:**
> - صفحة **بروفايل** المنظمة القديمة → 404
> - أي **طلب API** بيستخدم اسم المنظمة القديم → 404
> - منشنات الفرق (`@org/team`) بالاسم القديم
> - 🔴 **الأخطر:** الاسم القديم بيصير **متاح لأي حدا يحجزه فورا** — ولو حجزه حدا وعمل ريبو بنفس الاسم، بيدهس إعادة التوجيه تبعتك وبتنكسر الروابط فعلا
>
> **الخلاصة العملية ما تغيّرت، بس السبب تغيّر:** اختار اسم محايد **مرة وحدة** وما تعيد تسميته أصلا — مش لأن إعادة التسمية كارثة، بس لأنها ما إلها داعي. **اسم منظمة GitHub مش اسم البراند، ولا حدا باللجنة رح يشوفه.**

**ليش منظمة مش حسابك الشخصي؟** لأن المشروع بيصير ملك المشروع مش ملكك. لو حدا ترك الفريق، أو انضم واحد جديد، أو المشروع انحضن — ما في نقل ملكية. ومجانية.

**الأدوار:** الفاوندر = Owner. البقية = Member.

## 2️⃣ إنشاء الريبو — ٢ دقيقة

جوا المنظمة → **New repository**:

| الحقل | القيمة |
|---|---|
| الاسم | `wafa` |
| الوصف | `WhatsApp direct ordering platform for restaurants` |
| الرؤية | **Private** (اقرأ الملاحظة تحت) |
| README | ❌ **لا تأشّر** |
| .gitignore | ❌ **لا تأشّر** |
| License | ❌ **لا تأشّر** |

> **ليش ما نأشّر على الثلاثة؟** لأنهم موجودين بالحزمة أصلا. لو أشّرت، GitHub بيعمل commit أول، وأول push بيصير فيه تعارض بتصرف عليه نص ساعة بلا سبب.

> **📌 عن اسم الريبو `wafa`:** هون عادي تستخدمه حتى لو الاسم النهائي تغيّر. إعادة تسمية **الريبو** (مش المنظمة) بتعمل إعادة توجيه كاملة — توثيق GitHub بيقول إن كل عمليات `git clone` و `git fetch` و `git push` على العنوان القديم **بتضل تشتغل** زي ما هي على الجديد.
>
> **الاستثناء الوحيد:** لو استخدمت GitHub Action مستضاف بنفس الريبو — إعادة التوجيه ما بتشتغل عليه والـworkflow بيفشل. الـCI عندنا (`.github/workflows/ci.yml`) بيستخدم actions رسمية من `actions/*` مش محلية، فما في خطر.
>
> **يعني:** اسم المنظمة = اختاره محايد ولا تلمسه. اسم الريبو = عادي غيّره لاحقا.

### 🔴 Private مقابل Public — قرار له أثر عملي

| | Private (مجاني) | Public (مجاني) |
|---|---|---|
| حماية فرع main | ❌ **مش متاحة على الخطة المجانية** | ✅ متاحة |
| دقائق CI | ٢,٠٠٠/شهر | ♾️ بلا حدود |
| الكود ظاهر للناس | لا | نعم |

**يعني بالـPrivate المجاني ما بتقدر تمنع أحد تقنيا من الـpush على `main` مباشرة.** CI بيضل يشتغل ويبيّن أحمر على الـPR — بس ما بيقدر يوقف الدمج.

**التوصية:** ابقَ Private، وعوّض الحماية بـ**pre-push hook** (خطوة ٦) — بيوقف الكود السيء **قبل** ما يطلع من الجهاز أصلا، وهي حماية أقوى من حماية GitHub فعليا لأنها بتشتغل أبكر.

**٢,٠٠٠ دقيقة كافية؟** رحلة CI عنا ~٤ دقايق. ٥ مطورين × ٣ PRs/يوم × ٢٢ يوم ≈ ١,٣٢٠ دقيقة. **كافية بهامش ضيّق.** لو اقتربتوا من الحد، خلّوا CI يشتغل على PRs بس (مش على كل push) — أو حوّلوا الريبو Public.

### 🔴 قبل أول commit — تأكد إنه ما في `.env`

```bash
git status --short | grep -E "^\?\? \.env$" && echo "🔴 قف! .env رح ينرفع" || echo "✓ نظيف"
```

**ليش هالخطوة موجودة أصلا؟** لأن `.env` رح يحتوي على token واتساب ومفتاح بوابة الدفع. لما ترفعه على جيت، **ما بينمسح بحذف الملف** — بيضل بالـhistory للأبد. أي حدا عنده وصول للريبو (أو الإنترنت كله لو Public) بيقدر يطلعه. الحل الوحيد وقتها: تغيّر كل المفاتيح.

`.gitignore` بالحزمة بيمنعه أصلا. السطر فوق فحص ثاني.

```bash

git commit -m "chore: Sprint 0 foundation — schema, RLS, security gate, CI

- 13 tables, 19 indexes, RLS on 11 of them
- chain-isolation gate: 12 assertions + 3 negative controls
- Drizzle locked (ADR-001), 4 schema deltas documented (ADR-002)
- pnpm monorepo: 2 services + shared package"

git push -u origin main
```

## 6️⃣ 🔴 pre-push hook — الحماية الحقيقية

هذا بيشتغل **على جهاز المطور، قبل ما الكود يوصل GitHub أصلا**.

```bash
cd ~/wafa
pnpm add -D husky
pnpm exec husky init

cat > .husky/pre-push <<'EOF'
#!/usr/bin/env sh

branch=$(git rev-parse --abbrev-ref HEAD)
if [ "$branch" = "main" ]; then
  echo "🔴 ممنوع الـpush المباشر على main. اعمل فرع و PR."
  exit 1
fi

echo "▸ فحص الأنواع..."
pnpm typecheck || exit 1

echo "▸ البوابة الأمنية..."
pnpm test:security || {
  echo ""
  echo "🔴 بوابة عزل السلاسل حمرا. الـpush موقوف."
  echo "   هاد مش تحذير — هاد يعني إن مطعم ممكن يشوف بيانات مطعم تاني."
  exit 1
}
EOF
chmod +x .husky/pre-push
git add .husky && git commit -m "chore: pre-push hook — security gate + no direct push to main"
```

**بيمنع فعليا:** الـpush على `main` مباشرة · كود ما بيمر بفحص الأنواع · **أي كود بيكسر عزل المطاعم**.

## 9️⃣ تدفّق العمل اليومي — علّقه على الحيط

```bash
# ١. ابدأ من main محدّث
git checkout main && git pull

# ٢. فرع جديد للمهمة
git checkout -b feat/S0-04-auth-jwt

# ٣. اشتغل، وكوميت صغار

# ٤. ادفع (الـhook بيفحص تلقائيا)
git push -u origin feat/S0-04-auth-jwt

# ٥. افتح PR من الرابط اللي بيطلع بالتيرمنال
# ٦. انتظر CI يخضرّ + مراجعة واحدة
# ٧. Squash and merge → احذف الفرع
```


## ⚠️ ثلاث قواعد ما بتنكسر

**١. الـmigrations append-only.**
انبنت عند حدا؟ **ممنوع تعدّلها.** اعمل ملف جديد `0004_...`. لو عدّلت وحدة قديمة: جهازك فيه التعديل، جهاز زميلك لأ، والسيرفر لأ — وقاعدة بياناتكم صارت ثلاث قواعد مختلفة بتفشل بأشكال مختلفة.

**٢. `pnpm-lock.yaml` ينرفع دايما.**
ولا واحد يستخدم `npm install`. لو صار: `rm -rf node_modules package-lock.json && pnpm install`.

**٣. `.env` ما بيوصل جيت.**
لو صار بالغلط: **غيّر كل المفاتيح فورا** (توكن واتساب، JWT secret، كل شي). حذف الملف ما بيكفي — بيضل بالـhistory.
