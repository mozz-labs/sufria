## 2. ي-أ-1 · الهجرة 0014 + المرآة

```sql
BEGIN;
ALTER TABLE restaurants ADD COLUMN orders_paused_at timestamptz NULL;
ALTER TABLE menu_items  ADD COLUMN archived_at      timestamptz NULL;
ALTER TABLE menu_items
  ADD CONSTRAINT menu_items_archived_not_available
  CHECK (archived_at IS NULL OR is_available = false);
COMMIT;
```

- `orders_paused_at`: `NULL` = الطلبات شغّالة. غير هيك = موقفة من هاللحظة.
- `archived_at`: `NULL` = بالمنيو. غير هيك = مؤرشف من هاللحظة.
- **القيد هو الضمانة:** صنف مؤرشف ما بيقدر يكون متاح، حتى لو غلط الكود. وبما إنه المحرّك أصلا بيعتبر `is_available = false` مش موجود، **الأرشفة ما بدها ولا سطر بالمحرّك**.
- هيدر تعليق بالملف بنفس أسلوب الهجرات القائمة، بيشرح هالسببين.
- المرآة بـ`packages/shared/src/schema.ts` (عمودين)، و`test:db` بيمرق.

**الاختبارات:**
- 🔴 بـ`tests/db` (نفس مكان الفحوصات الحرجة): صف `archived_at` مش فاضي و`is_available = true` ← بيرفضه القيد (`23514`). وصف مؤرشف ومطفي ← بيقبله.

**ضابط كسر:** على نسخة الاختبارات بس: `ALTER TABLE menu_items DROP CONSTRAINT menu_items_archived_not_available` ← بيسقط اختبار القيد لحاله. بعدين رجّعه (`ADD CONSTRAINT` بنفس التعريف) وتأكد إنه رجع.

## 4. ي-أ-3 · المحرّك

**الترتيب الجديد بـ`handleInbound`** (بعد ما `readRestaurant` تقرأ `orders_paused_at` كمان):

1. المهلة (ح) **بلا تغيير**.
2. **جلسة نشطة + الطلبات موقفة** ← `ORDERS_PAUSED_AR`، والجلسة **ما بتنلمس** (لا حالة، لا سلّة، لا `last_message_at`). ولا طلب بينكتب. 🔴 هاد بيشمل «أكّد».
3. توجيه الجلسة النشطة **بلا تغيير**، إلا: **أي مكان كان رح يبعت منيو بصفر أصناف** (مثلا «منيو») بيبعت `ORDERS_PAUSED_AR` بداله، والجلسة ما بتنلمس.
4. بوابة الساعات **بلا تغيير** (المسكّر بيغلب الإيقاف للمحادثة الجديدة).
5. **محادثة جديدة + الطلبات موقفة** ← `ORDERS_PAUSED_AR`، **ولا جلسة بتنفتح** (زي المسكّر).
6. `prepareMenu`. **إذا المنيو فيه صفر أصناف** ← `ORDERS_PAUSED_AR`، **ولا جلسة بتنفتح**.
7. الباقي بلا تغيير.

- **سطر سجل `info`** لكل رد إيقاف أو منيو فاضي: المطعم · السبب (`paused` أو `empty_menu`) · الرقم **مقنّع**.
- **«الصفر أصناف» بنفس معيار المنيو بالزبط** (صنف متاح بتصنيف فعّال). معيار مكتوب بمكان واحد، مش نسخة تانية.
- **الأرشفة:** ولا تعديل بالمحرّك (القيد بـ§2). إذا فحص ي-أ-0 #4 طلّع مكان ما بيقرأ `is_available` ← 🛑 قبل هون.
- **سباق معروف ومقبول:** إيقاف بينحفظ بنفس الملّي ثانية اللي «أكّد» عم تكتب فيها الطلب ممكن يمرّق طلب واحد. **سجّله بـKnown gaps**، بلا قفل جديد.

## 5. ي-أ-4 · الـAPI — العقود

كل المسارات تحت `RestaurantContextGuard` و`x-restaurant-id` زي القائم. **المطعم من الحارس، مش من الجسم ولا الـquery.**

| المسار | الجسم | الرد | ملاحظات |
|---|---|---|---|
| `GET /menu-items` | — | `{ items }` | كل صنف **+ `categoryId` و`categoryName`**. **المؤرشف ما بيطلع.** الترتيب زي اليوم |
| `GET /menu-items?archived=true` | — | `{ items }` | المؤرشف بس، كل صنف + `archivedAt`، الأحدث أولا |
| `GET /menu-categories` | — | `{ categories: [{ id, name }] }` | الفعّالة بس، بترتيب المنيو |
| `POST /menu-items` | `{ categoryId, name, price }` | 201 + الصنف | **متاح من أول لحظة**، بآخر تصنيفه (`display_order` = الأكبر + 1). تصنيف مش للمطعم أو مش فعّال ← 404 |
| `PATCH /menu-items/:id` | واحد أو أكتر من `name` · `price` · `isAvailable`، **أو** `archived` لحاله | 200 + الصنف | تفاصيل تحت |
| `POST /menu-items/enable-all` | — | `{ enabled: number }` | بيشغّل كل صنف مطفي **مش مؤرشف**. `enabled` = كم صنف تغيّر |
| `GET /restaurant/settings` | — | + `ordersPausedAt: string \| null` | — |
| `PATCH /restaurant/orders-pause` | `{ paused: boolean }` | `{ ordersPausedAt: string \| null }` | إيقاف وهي موقفة بيحتفظ بالوقت الأول · رجوع وهي شغّالة ← `null` و200 |

**`PATCH /menu-items/:id` بالتفصيل:**
- `archived: true` ← `archived_at = now()` و`is_available = false` بنفس الأمر. مؤرشف أصلا ← بيحتفظ بالوقت الأول.
- `archived: false` ← `archived_at = NULL`، **و`is_available` بيضل `false`** (القرار 4).
- `archived` مع أي حقل تاني بنفس الجسم ← 400.
- **أي تعديل على صنف مؤرشف غير `archived: false`** ← 409 `item_archived`. ومنها `isAvailable: true`: القيد بيرفضه بالقاعدة، والـAPI بتحوّل الرفض لـ409 (مش 500).
- `name` و`price` بيمرّوا على تطبيع §3 قبل التحقق. المرفوض ← 400.

**🔴 حماية الـ4096 (`menu_too_long`):**
- **على:** `POST /menu-items` · `PATCH` فيه `name` أو `price` أو `isAvailable: true` · `enable-all`.
- **الطريقة:** جوّا نفس المعاملة: نفّذ التعديل ← ابني **أول رسالة** (الترحيب باسم المطعم + المنيو) **بدالة shared نفسها** (§3) من القاعدة ← عدّ بنفس القاعدة. **إذا الطول بعد > 4096 وأطول من قبل** ← رجوع عن المعاملة، و409:

```json
{ "statusCode": 409, "error": "Conflict", "code": "menu_too_long",
  "message": "...", "length": 4123, "limit": 4096 }
```

- «وأطول من قبل»: منيو طويل أصلا (مثلا من سكربت التهيئة) ما بيمنع تعديل ما بيطوّله، وبيسمح بكل تعديل بيقصّره. هيك بيتعافى.
- `item_archived` بنفس الشكل بلا `length` و`limit`. الأنواع بـshared (§3 بند 4).

**الاختبارات** (على نمط `menu-items.test.ts` القائم):
