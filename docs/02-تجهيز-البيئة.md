## 🔴 القرار الأهم: كلكم رح تشتغلوا على WSL2، مش على ويندوز مباشرة

**WSL2 = Ubuntu حقيقي جوا ويندوز.** بتفتحه من قائمة ابدأ زي أي برنامج.

**ليش؟ مش تفضيل شخصي — أربعة أسباب فنية:**

1. **السيرفر رح يكون Linux.** بالتطوير على ويندوز، بتكتشف فروقات المسارات وصلاحيات الملفات ونهايات الأسطر **يوم الـdeploy**، وهاد أسوأ يوم لتكتشفها فيه.
2. **`negative-controls.sh` سكريبت bash.** على ويندوز ما بيشتغل. البوابة الأمنية بتصير "بننفّذها على السيرفر بس" — يعني عمليا ما بتنفّذ.
3. **`.env` وملفات SQL فيها عربي.** ويندوز بيحفظ بترميز مختلف بشكل افتراضي وبيكسر النصوص العربية بشكل صامت.
4. **نهايات الأسطر (CRLF).** ويندوز بيحط `\r\n`. أي سكريبت bash بيصير `command not found: bash^M` — وهي أكتر رسالة خطأ محيّرة بالوجود.

**الوقت: ١٥ دقيقة تنصيب. بيوفروا أيام.**

## 1️⃣ تنصيب WSL2 — ١٥ دقيقة

افتح **PowerShell كمسؤول** (زر ويندوز → اكتب PowerShell → كليك يمين → Run as administrator):

```powershell
wsl --install -d Ubuntu-24.04
```

بعدها **أعد تشغيل الجهاز**. أول ما ترجع، بيفتح شباك أسود بيطلب اسم مستخدم وكلمة سر — **هدول جداد وخاصين بـUbuntu، مش تبع ويندوز**. اكتبهم واحفظهم.

> **كلمة السر ما بتظهر وإنت بتكتب** (ولا نجوم ولا شي). هيك المفروض. اكتب واضغط Enter.

**تأكد إنه اشتغل:** افتح PowerShell عادي:
```powershell
wsl -l -v
```
لازم تشوف `Ubuntu-24.04    Running    2`. الرقم **٢** مهم.

**من هون ورايح: كل الأوامر بتنكتب جوا Ubuntu**، مش PowerShell. تفتحه من قائمة ابدأ → "Ubuntu".

### 🔴 لو الإنترنت ما اشتغل جوا Ubuntu — اقرأ هذا قبل ما تكمّل

> **صار فعليا عند الفاوندر يوم ١٦ أغسطس وأكل أكتر من ساعة. اقرأه قبل ما توصله.**

**الأعراض** — أي وحدة من هدول لما تشغّل `apt`:

```
Cannot initiate the connection to archive.ubuntu.com:80 (2620:2d:...) - connect (101: Network is unreachable)
Could not connect to security.ubuntu.com:80 (91.189.91.81), connection timed out
E: Unable to fetch some archives
```

**الفحص الحاسم** — من Ubuntu:

```bash
curl -4 -s -o /dev/null -w "%{http_code}\n" --max-time 10 https://www.google.com
```

`200` = الشبكة سليمة، المشكلة بمكان تاني. **`000` = اتبع الحل تحت.**

> **القاعدة:** لو **ويندوز عنده إنترنت وأوبونتو لأ**، فالعطل بطبقة الشبكة الافتراضية تبع WSL — مش بمزوّد الإنترنت ولا بمستودعات أوبونتو. **لا تضيّع وقتك تبدّل مرايا `apt`.**

**الحل — من PowerShell (مش Ubuntu):**

```powershell
wsl --update
@"
[wsl2]
networkingMode=mirrored
dnsTunneling=true
autoProxy=true
"@ | Set-Content -Encoding ASCII "$env:USERPROFILE\.wslconfig"
wsl --shutdown
```

استنى ١٥ ثانية، افتح Ubuntu من جديد، وأعد فحص الـ`curl` فوق.

**شو بيعمل `networkingMode=mirrored`:** بيخلي Ubuntu يستخدم **شبكة ويندوز نفسها مباشرة** بدل ما يبني شبكة افتراضية معزولة (NAT). بيتخطى الطبقة المعطّلة كليا.

⚠️ **بيحتاج ويندوز ١١ + WSL 2.0 أو أحدث.** على ويندوز ١٠ الإعداد بينتجاهل بصمت — وقتها الشك بيروح على جدار الحماية أو الأنتي فايروس أو VPN.

**علاج إضافي لو ظهرت أخطاء IPv6 بالتحديد** (عناوين بالشكل `2620:2d:...`) — من Ubuntu:

```bash
echo 'Acquire::ForceIPv4 "true";' | sudo tee /etc/apt/apt.conf.d/99force-ipv4
```

بيجبر `apt` يستخدم IPv4 دايما. بينحط مرة وحدة وبيضل.

### 🔴 مصيدة تانية: `df` جوّا Ubuntu بيكذب عليك

لو ظهرلك `Input/output error` على أوامر كانت شغالة قبل دقيقة (حتى `node` أو `ls` أو `head`) — **مساحة القرص، مش عطل بالبرنامج.**

```
$ df -h /
/dev/sdd  1007G  1.9G  954G  1%  /      ← ٩٥٤ غيغا فاضية؟ ❌ رقم وهمي
```

قرص WSL **متناثر (sparse)**: بيعلن سعة ضخمة، بس فعليا محدود بالمساحة الفاضية على `C:` بويندوز. لما `C:` تمتلئ، الكتابة بتفشل — و**أوبونتو ما بيعرف السبب**، فبيعطيك `Input/output error` بدل `No space left on device`.

**القاعدة: افحص المساحة من ويندوز، مش من أوبونتو.** من PowerShell:
```powershell
Get-PSDrive -PSProvider FileSystem | Select Name,@{n='Free_GB';e={[math]::Round($_.Free/1GB,1)}}
```

**العلاج لما يصير:**
1. فضّي مساحة على `C:` (`powercfg /h off` بيفضّي ٦–١٣ غيغا فورا)
2. `wsl --shutdown` من PowerShell، وافتح Ubuntu من جديد
3. 🔴 **أي إشي انكتب وقت الامتلاء صار تالف.** لو `node -v` بيعطي `Segmentation fault`، أعد تنصيبه: `nvm uninstall 24 && nvm install 24`

**المساحة المطلوبة للمشروع:** `node_modules` ~٢ غيغا · Docker + صورة PostgreSQL ~٣ غيغا. **خلّي ١٥–٢٠ غيغا فاضية قبل ما تبلش.**

## 2️⃣ تنصيب Docker Desktop — ١٠ دقايق

**ليش Docker؟** بدل ما كل واحد ينصّب PostgreSQL على جهازه (ونسخة كل واحد تطلع مختلفة)، Docker بيشغّل **نفس النسخة بالضبط** عند الخمسة. ومسح كل شي والبدء من نظيف = أمر واحد.

1. نزّل من [docker.com/products/docker-desktop](https://www.docker.com/products/docker-desktop/)
2. نصّبه (اترك كل الخيارات الافتراضية)
3. **الخطوة اللي الكل بينساها:** افتح Docker Desktop → ⚙️ Settings → **Resources** → **WSL Integration** → فعّل `Ubuntu-24.04` → **Apply & Restart**

**تأكد** — من **Ubuntu** (مش PowerShell):
```bash
docker --version
```
لو طلعت نسخة → تمام. لو `command not found` → ارجع للخطوة ٣.

## 3️⃣ Node.js 24 + pnpm — ١٠ دقايق

**Node 24 هي النسخة المستقرة الرسمية (Active LTS) حاليا.** مش الأحدث — ٢٦ أحدث بس لسا ما صارت LTS. بالمشاريع الجدية بتستخدم LTS.

من **Ubuntu**:

```bash
# أدوات أساسية
sudo apt update && sudo apt install -y curl git unzip build-essential postgresql-client-16

# nvm — بيخليك تبدّل بين نسخ Node بسهولة
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.1/install.sh | bash
source ~/.bashrc

# Node 24 وتثبيتها كافتراضية
nvm install 24
nvm alias default 24

# pnpm عبر corepack (الطريقة الرسمية — بتضمن نفس النسخة عند الكل)
corepack enable
corepack prepare pnpm@9.15.0 --activate
```

**تأكد:**
```bash
node -v     # v24.x.x
pnpm -v     # 9.15.0
psql --version
```

> **ليش pnpm مش npm؟** ثلاثة أسباب: أسرع كتير، بيوفر مساحة القرص (بيخزن كل حزمة مرة وحدة للجهاز كله)، **وبيدعم الـworkspaces** — اللي بيخلي `apps/` و`packages/` تشتغل مع بعض بدون نشر حزم. المشروع مبني على هالميزة.
>
> **مهم:** ما حدا يستخدم `npm install` بهالمشروع. `npm` بيولّد `package-lock.json` وبيتضارب مع `pnpm-lock.yaml`. لو صار بالغلط: `rm -rf node_modules package-lock.json && pnpm install`.

## 6️⃣ تشغيل المشروع — ١٠ دقايق

```bash
cd ~
git clone git@github.com:<اسم-المنظمة>/wafa.git
cd wafa

cp .env.example .env      # 🔴 لا ترفع .env على جيت أبدا
pnpm install
pnpm db:up                # بيشغّل PostgreSQL بـDocker وبينتظر لحد ما يجهز
pnpm db:migrate           # بيبني الـ١٣ جدول
pnpm db:seed              # بيانات اختبار
pnpm test:security        # 🔴 لحظة الحقيقة
```

**النتيجة المتوقعة:**
```
NOTICE:  ALL 12 ASSERTIONS PASSED — chain isolation gate is green
  ✓ gate correctly went red: RLS disabled on orders
  ✓ gate correctly went red: app role granted SUPERUSER
  ✓ session-scoped context leaks as expected (this is why A4 exists)
✓ البوابة الأمنية خضرا
```

**لو شفت هالسطور — بيئتك مضبوطة ١٠٠٪. جاهز تشتغل.**

### أوامر رح تستخدمها يوميا

| الأمر | شو بيعمل |
|---|---|
| `pnpm db:up` | يشغّل قاعدة البيانات |
| `pnpm db:down` | يوقفها |
| `pnpm db:reset` | 🔴 **يمسح كل البيانات** ويرجّع من نظيف |
| `pnpm dev` | يشغّل كل الخدمات مع بعض |
| `pnpm typecheck` | يفحص الأنواع |
| `pnpm verify` | **كل شي** — شغّله قبل أي push |

### 👨‍💻 الباك اند (الاثنين)

```bash
# NestJS CLI — بيولّد modules/controllers/services بأمر واحد
pnpm add -g @nestjs/cli
nest --version
```

**اقرأ قبل الأحد ١٦ أغسطس** (إنتوا اشتغلتوا باك اند بس بأطر مختلفة — هالساعتين بيوفروا يومين تخبّط):

1. **[NestJS Overview](https://docs.nestjs.com/)** — أول ٥ صفحات بس: Controllers, Providers, Modules, Middleware, Guards.
   💡 لو جاي من Express/Spring: NestJS بتشبه Spring كتير أكتر من Express. `@Injectable` = `@Service`، والـmodules زي الـ`@Configuration`.
2. **[Drizzle — Select / Insert / Update](https://orm.drizzle.team/docs/select)** — ٢٠ دقيقة. Drizzle **مش** ORM بمعنى Hibernate/TypeORM: ما في lazy loading ولا entity manager. بتكتب SQL بصيغة TypeScript. لو مرتاح بالـSQL، هي أسهل مما تتوقع.
3. **`apps/conversation-engine/src/db/critical-primitives.ts`** ← 🔴 **اقرأه بتمعّن.** الأربع عمليات اللي كل صحة النظام معلقة فيهم.
4. **[PostgreSQL RLS](https://www.postgresql.org/docs/16/ddl-rowsecurity.html)** — ١٥ دقيقة. لازم تفهم `USING` مقابل `WITH CHECK`.

**⚠️ عادات لازم تتغير:** لو تعوّدت على `findOne()` وبعدين `save()` — بهالمشروع في ٤ أماكن **ممنوعة تماما**. اقرأ `critical-primitives.ts` لتعرف وين وليش.

## المشاكل الشائعة

| العرض | السبب | الحل |
|---|---|---|
| `docker: command not found` جوا Ubuntu | WSL Integration مش مفعّلة | Docker Desktop → Settings → Resources → WSL Integration |
| `bash\r: command not found` | نهايات أسطر ويندوز | `git config --global core.autocrlf input` ثم `rm -rf wafa && git clone` من جديد |
| `port 5432 already in use` | عندك PostgreSQL منصّب على ويندوز | أوقفه: `services.msc` → PostgreSQL → Stop |
| العربي بيطلع `?????` | الترميز | تأكد إنك جوا WSL مش PowerShell |
| `pnpm: command not found` بعد إعادة فتح | corepack ما انحفظ | `corepack enable && corepack prepare pnpm@9.15.0 --activate` |
| `EACCES permission denied` | استخدمت `sudo npm` | ما تستخدم sudo مع pnpm أبدا |
| المشروع بطيء جدا | حاطط الملفات بـ`/mnt/c/` | 🔴 لازم يكون بـ`~/wafa` (نظام ملفات Linux). القراءة من قرص ويندوز أبطأ ١٠× |
